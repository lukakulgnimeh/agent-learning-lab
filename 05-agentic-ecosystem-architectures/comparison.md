# Comparison
 
| Criteria | n8n | Codex | Claude Code | LangGraph |
|---|---|---|---|---|
| **Basic Model** | Visual node graph: the graph is the control flow | Agent harness: model-driven reasoning loop, structured by `AGENTS.md` + skills + `.codex/`config | Agent harness: single-model reasoning loop, structured by `CLAUDE.md` + skills + `.claude/` config | *(Part B not started)* |
| **Developer Control** | Every node and connection authored explicitly; full control flow hand-wired | Project context (`AGENTS.md`), skills, subagent/tool config; control flow itself left to the model | Project context (`CLAUDE.md`), subagent `tools:` allowlist, `settings.json` permissions; control flow left to the model | |
| **Agent Autonomy/Role** | None by default; confined to an optional "AI Agent" node's own tool choice | High - model decides when/whether to delegate and how to complete a task; can adapt when delegation is unavailable | High - model decides when/whether to delegate (via subagent `description` matching) and how to complete a task | |
| **Control/Determinism** | Fully deterministic node-by-node, except inside an AI Agent node | Low by default; instructions, available tools and permissions constrain execution, but the path remains model-directed | Low by default; two hard gates (`tools:`, `settings.json`); everything else manufactured via literal prompt wording | |
| **Transparency/Observability** | Per-node execution log; input/output visible for every run in the (debugging-) UI | Local session transcript; subagent internals not surfaced upward, only final report | Local session transcript (`~/.claude/projects/`); subagent internals not surfaced upward, only final report | |
| **State/Context** | Explicit JSON passed between connected nodes; no hidden state | No persistent state by default; project context comes from files/configuration, while the active session provides conversational context | No persistent state by default; resumed session reattaches transcript, fresh session starts empty | |
| **Tools** | Built-in/community nodes, or a generic HTTP Request node, wired explicitly per workflow | Built-in tools + MCP for custom/authenticated tools; built-in subagents receive access to skills and tools by default | Built-in tools (`WebSearch`, `WebFetch`, `Bash`) + MCP for genuinely custom/authenticated tools; MCP is the only mechanism keeping a secret out of model context | |
| **Delegation/Subagents** | Explicit "Execute Workflow" sub-workflow node, or parallel branches, all hand-wired; define communication protocols, responsibilities, interfaces | Subagents can receive relevant skill/tool access; delegation is model-directed and can fall back to direct tool use | Custom subagents (`.claude/agents/*.md`): explicit `description` (routing) + `tools:` allowlist; strictly parent-driven, one report back, no mid-run questions | |
| **Extensibility** | Install community nodes, or write a custom code node (JS/Python) | New markdown role/skill files; custom tools via MCP | New markdown role/skill files; custom tools via MCP (a dependency-free single-file server is viable) | |
| **Suitable Problem Types** | Deterministic, repeatable integrations/automations, explicit orchestration, optionally with bounded LLM decision points | Coding-adjacent agentic work; favors open-ended tasks with dynamic planning and tool use | Coding-adjacent agentic work with explicit role/permission boundaries; prototypes where isolation and constrained roles matter more than strict determinism | |
