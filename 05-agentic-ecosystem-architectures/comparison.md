# Comparison
 
| Criteria | n8n | Codex | Claude Code | LangGraph |
|---|---|---|---|---|
| **Basic Model** | Visual node graph: the graph is the control flow | Agent harness: model-driven reasoning loop, structured by `AGENTS.md` + skills + `.codex/`config | Agent harness: single-model reasoning loop, structured by `CLAUDE.md` + skills + `.claude/` config | Graph-based: developer-defined stateful graph or framework-provided agent graph; supports deterministic routing, ReAct loops and nested agents |
| **Developer Control** | Every node and connection authored explicitly; full control flow hand-wired | Project context (`AGENTS.md`), skills, subagent/tool config; control flow itself left to the model | Project context (`CLAUDE.md`), subagent `tools:` allowlist, `settings.json` permissions; control flow left to the model | State schema, nodes, edges, routing, tools and agent composition can be defined explicitly or decided to be moved to the framework |
| **Agent Autonomy/Role** | None by default; confined to an optional "AI Agent" node's own tool choice | High - model decides when/whether to delegate and how to complete a task; can adapt when delegation is unavailable | High - model decides when/whether to delegate (via subagent `description` matching) and how to complete a task | Variable - from deterministic routing to model-driven tool selection and multi-agent delegation; autonomy is defined by how much control is delegated to the model |
| **Control/Determinism** | Fully deterministic node-by-node, except inside an AI Agent node | Low by default; instructions, available tools and permissions constrain execution, but the path remains model-directed | Low by default; two hard gates (`tools:`, `settings.json`); everything else manufactured via literal prompt wording | Explicit routing can be deterministic; ReAct and agent composition make execution increasingly model-directed |
| **Transparency/Observability** | Per-node execution log; input/output visible for every run in the (debugging-) UI | Local session transcript; subagent internals not surfaced upward, only final report | Local session transcript (`~/.claude/projects/`); subagent internals not surfaced upward, only final report | Explicit graphs expose nodes, edges and state transitions; custom graphs and abstractions increasingly hide more of the execution structure |
| **State/Context** | Explicit JSON passed between connected nodes; no hidden state | No persistent state by default; project context comes from files/configuration, while the active session provides conversational context | No persistent state by default; resumed session reattaches transcript, fresh session starts empty | Explicit shared state across nodes; MessagesState standard context, while checkpointing can add persistent state |
| **Tools** | Built-in/community nodes, or a generic HTTP Request node, wired explicitly per workflow | Built-in tools + MCP for custom/authenticated tools; built-in subagents receive access to skills and tools by default | Built-in tools (`WebSearch`, `WebFetch`, `Bash`) + MCP for genuinely custom/authenticated tools; MCP is the only mechanism keeping a secret out of model context | Tools are developer-defined capabilities; ToolNode executes model-generated tool calls, while tools can also wrap complete agents or external APIs |
| **Delegation/Subagents** | Explicit "Execute Workflow" sub-workflow node, or parallel branches, all hand-wired; define communication protocols, responsibilities, interfaces | Subagents can receive relevant skill/tool access; delegation is model-directed and can fall back to direct tool use | Custom subagents (`.claude/agents/*.md`): explicit `description` (routing) + `tools:` allowlist; strictly parent-driven, one report back, no mid-run questions | Subagents: composed as independent graphs or exposed as tools to a supervisor, i.e. delegation explicit or model-directed |
| **Extensibility** | Install community nodes, or write a custom code node (JS/Python) | New markdown role/skill files; custom tools via MCP | New markdown role/skill files; custom tools via MCP (a dependency-free single-file server is viable) | Add nodes, edges, state fields, tools or subgraphs/agents; higher-level abstractions allow simplification |
| **Suitable Problem Types** | Deterministic, repeatable integrations/automations, explicit orchestration, optionally with bounded LLM decision points | Coding-adjacent agentic work; favors open-ended tasks with dynamic planning and tool use | Coding-adjacent agentic work with explicit role/permission boundaries; prototypes where isolation and constrained roles matter more than strict determinism | Stateful, multi-step agentic systems requiring a tunable balance between explicit orchestration and model autonomy; useful for branching, looping, tool use and multi-agent workflows |
